1. Why 16 threads did not run twice as fast as 8 threads on an 8-core CPU
Shared Execution Pipelines: An 8-core CPU has only 8 physical compute cores. Running 16 threads relies on Simultaneous Multithreading which provides logical thread contexts that share the same physical execution units rather than duplicating them.
Compute Saturation: Because the Monte Carlo loop is entirely compute-bound, the physical execution ports are already saturated at 8 threads. SMT threads cannot double throughput because there are no idle functional units left to exploit.

2. Why the synchronized version in Part 2 was slower than a single core
Critical Section Serialization: Requiring threads to acquire a mutual exclusion lock on every loop iteration serializes execution, eliminating concurrency.
Lock Overhead & Bus Contention: Cores spend the vast majority of their clock cycles arbitrating lock access, stalling on memory bus locks, and incurring OS kernel context switches. A single-threaded loop modifies its accumulator directly in local registers/cache with zero synchronization penalty.
